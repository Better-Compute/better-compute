# Better Compute documentation site

Next.js 16 + [Fumadocs](https://fumadocs.dev) 16, styled with [BoardUI](https://www.boardui.com) exactly like the
Better IAM docs. Content lives in `content/docs`, the reference section is generated from the live packages, and
the site adds Mermaid diagrams, glossary hover cards, section-filtered search, an MCP endpoint, and LLM-friendly
Markdown endpoints.

pnpm 11.19.0 is pinned by the workspace. From the repository root, `node node_modules/pnpm/bin/pnpm.mjs` is that
copy; plain `pnpm` works when your global pnpm is 11.x.

```sh
pnpm build                                        # tsc -b: the packages the generator loads
node apps/docs/scripts/generate.mjs               # generated/*.json + content/docs/reference/** (--check in CI)
pnpm --filter @better-compute/docs dev            # http://localhost:4100
node apps/docs/scripts/check-content.mjs          # frontmatter, meta.json, links and #anchors, code fences
pnpm --filter @better-compute/docs typecheck      # next typegen && tsc --noEmit
pnpm --filter @better-compute/docs build
node apps/docs/scripts/generate-icons.mjs         # after changing the logo mark
```

Type-checking needs the `.source` folder that fumadocs-mdx writes (`next dev` and `next build` write it too; on a
fresh checkout run `node node_modules/fumadocs-mdx/bin.js` in `apps/docs` first).

| Path                                                                                        | What it is                                                                                                       |
| ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `content/docs/{guides,extending,daemon,operations,reference}`                               | The five sidebar sections (folders whose `meta.json` has `"root": true`)                                         |

## Design system

The site is monochrome and built on [BoardUI](https://www.boardui.com), identical to the Better IAM docs site: its
components are source files in this app (`npx boardui@latest add <name>` from `apps/docs` adds more), and every
color is a BoardUI semantic token.

- `styles/theme.css`, `styles/typography.css`: BoardUI's tokens and type ramp, unmodified (`text-body-medium`,
  `bg-background-primary-default`, `border-border-button-default`, ...).
- `styles/monochrome.css`: the site's layer on top. It turns BoardUI's accent ramp neutral (black controls in light
  mode, white in dark), and maps Fumadocs' `--color-fd-*` palette onto the same tokens so the docs shell matches.
- `components/base/*`, `utils/cx.ts`: BoardUI components. Two local changes, marked in the source: the primary
  button label and the selected switch thumb read tokens, so they invert correctly in dark mode. Icons come from
  `react-icons/ri` (the same Remix Icon set BoardUI uses) instead of `@remixicon/react`.
- `components/application/theme/theme-toggle.tsx`: BoardUI's theme toggle, backed by next-themes.
- `components/site/*`: the marketing shell (header, footer, Lenis smooth scrolling, and the rail frame every
  landing band aligns to). `components/docs/*`: BoardUI versions of Fumadocs' `Callout` and `Card`.
- `components/logo.tsx`: the mark, a solid chip with its die window cut out, drawn as one even-odd path on a 24 px
  grid in the current color, beside the "Better" and secondary-colored "Compute" wordmark.
- `lib/code-themes.ts`: grayscale Shiki themes for every code block.

No hues and no radial gradients: states are told apart by weight (solid ink, outline, dashed, hatched).

## Deploying

The package is private: `pnpm publish -r` skips it. Nothing in this repository is published to npm yet (Better
Compute depends on Better IAM through vendored tarballs until Better IAM publishes), so the site builds against the
workspace: `better-compute` is a `workspace:*` dependency.

[`Dockerfile`](Dockerfile) builds the site from the repository root: install with the pinned pnpm
(`--frozen-lockfile`), `tsc -b` for the packages, `scripts/generate.mjs` for the reference, then `next build`. It
runs `next start` on `$PORT` (3000 when unset).

```sh
docker build -f apps/docs/Dockerfile -t better-compute-docs .
docker run -p 3000:3000 -e PORT=3000 better-compute-docs
```

Build arguments, read at build time and baked into the static pages:

| Variable                             | Default                                            | Purpose                                                                                |
| ------------------------------------ | -------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `DOCS_SITE_URL`                      | `http://localhost:4100`                            | Canonical origin (metadata, sitemap, `llms.txt`, social cards); `www.` redirects to it |
| `NEXT_PUBLIC_DOCS_REPOSITORY_URL`    | `https://github.com/better-compute/better-compute` | GitHub button, "Edit this page", source, and issue links                               |
| `NEXT_PUBLIC_DOCS_REPOSITORY_BRANCH` | `main`                                             | Branch for source and edit links                                                       |
| `DOCS_X_HANDLE`                      | unset                                              | The site's X account (`@name`) as `twitter:site` and `twitter:creator` on link cards   |
| `DOCS_GOOGLE_SITE_VERIFICATION`      | unset                                              | Google Search Console ownership token                                                  |
| `DOCS_BING_SITE_VERIFICATION`        | unset                                              | Bing Webmaster Tools ownership token (`msvalidate.01`)                                 |
| `DOCS_YANDEX_VERIFICATION`           | unset                                              | Yandex Webmaster ownership token                                                       |
| `NEXT_DIST_DIR`                      | `.next`                                            | Output directory, so concurrent `next dev` and `next build` runs do not collide        |

## Search and social metadata

Every page has a title, description, canonical URL, keywords, Open Graph and X card tags, and a 1200×630 social
card. Docs pages add `article:*` tags, Slack's "Section" and "Reading time" labels, and schema.org `TechArticle` and
`BreadcrumbList` data. The home page describes the site, the software, and its creator in JSON-LD.

| Path                                                                               | What it is                                                                                   |
| ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `lib/metadata.ts`                                                                  | Site title, description, and keywords; section names; `pageMetadata()`; JSON-LD builders     |
| `lib/docs-seo.ts`                                                                  | A docs page's document title, section trail, keywords, and breadcrumbs                       |
| `lib/og.tsx`, `lib/og-fonts.ts`                                                    | The social card renderer (Inter and JetBrains Mono, fetched from Google Fonts at build time) |
| `app/og/docs/[...slug]/route.tsx`, `app/og/[image]/route.tsx`                      | Cards for docs pages (`/og/docs/{slug}/image.png`) and the home page                         |
| `app/manifest.ts`, `public/{favicon.ico,icon.svg,apple-touch-icon.png,icon-*.png}` | Web app manifest and icons                                                                   |
| `app/robots.ts`, `app/sitemap.ts`                                                  | Every crawler everywhere except `/api/`; the home page and every docs page                   |

The icons are drawn from the logo mark in `components/logo.tsx` (`logoMarkPath`, which `lib/og.tsx` also uses).
After changing the mark, update the copy in `scripts/generate-icons.mjs` and run
`node apps/docs/scripts/generate-icons.mjs` to redraw every icon. `llms.txt` and `llms-full.txt` are served
`noindex`, and the Markdown copies (`/docs/x.md`) name their HTML page as canonical.

## How the reference is generated

`scripts/generate.mjs` reads the repository, never a hand-maintained list. It loads the built packages (run
`tsc -b` first; it names any missing build) and constructs a control plane with **every module registered**:
`provisionModule` with `metal()`, `vps()`, `eventsModule`, `fleetModule`, `rolloutModule` and `auditModule` beside
the built-in node controllers, `inventory` and `capacity`. The control plane uses a PGlite executor that is never
opened and an `IamPort` that refuses every call, so the registry is exactly the one a full deployment serves.

- **API** (`generated/api.json`, `reference/api/*.mdx`): every row of core's `apiSurface` (PLAN.md §9.2) with its
  kind, IAM action and resource (`compute:reservations:create` @ `compute-pool`), alternatives, and phase. A method
  the registry serves is `registered`; one it does not is `planned` for its phase. Registered methods outside §9.2
  are added too. One page per group (slug: the group in kebab case), plus the index with every group.
- **Errors** (`errors.json`, `reference/errors.mdx`): core's `errorCodes` with `defaultStatus`.
- **CLI** (`cli.json`, `reference/cli.mdx`): `cliManifest()` of `@better-compute/cli`: commands by group, usage,
  flags with defaults and environment variables, examples.
- **Command kinds** (`command-kinds.json`, `reference/command-kinds.mdx`): `registry.commandKinds` with lane, roles,
  retry-safety, self-termination, attestation, destructiveness, timeout, and payload type.
- **Modules** (`modules.json`, `reference/modules.mdx`): each module's API groups and migrations, and every job in
  `compute.jobs`.
- **Packages** (`packages.json`, `reference/packages.mdx`): every `packages/*/package.json`: name, description,
  privacy, and entry points.

Hand-written text comes from `descriptions/`: `api/{group}.md` holds an overview paragraph, then `## method`
sections whose first paragraph becomes the method's summary; `errors.md` holds `## CODE` sections. A heading that
names no method or code fails the run, so renamed methods cannot silently drop their text. Output is formatted with
the repository's Prettier config. `--check` writes nothing and fails when any generated file is out of date or
stale; a normal run also deletes stale files in the generated folders. The reference section's own `meta.json`,
index, glossary, roadmap, AI, and changelog pages are hand-written.

## Authoring conventions

**Files.** One `.mdx` file per page. A folder's `meta.json` sets its sidebar `title`, `icon`, and page order
(`{"title": "Capacity", "icon": "Gauge", "pages": ["index", "pools", "placement"]}`); root sections add
`"root": true` and a `description`. `index.mdx` is the folder's landing page, served at the folder URL
(`/docs/guides/capacity`).

**Frontmatter.**

```yaml
---
title: Reservations # short, sentence case
description: One sentence, at most ~160 characters (search snippet, social card, llms.txt summary).
metaTitle: GPU reservations # optional, when the title is too terse out of context; under ~47 chars
icon: Cpu # optional; an export name of lib/icons.ts
status: new # optional: new | beta | experimental | deprecated
packages: ['@better-compute/capacity'] # optional
sources: ['packages/capacity/src/reservations.ts', 'PLAN.md'] # repo-relative files the page was written from
---
```

The document title is `metaTitle` (or `title`) plus " | Better Compute", so keep `metaTitle` under about 47
characters. API reference groups are titled "{group} API" automatically.

**Voice.** Second person, present tense, short sentences. Explain what a feature is for before how to use it.
Sentence-case headings. `##` headings form the page's table of contents; use `###` below them. No marketing
language, no emoji, no exclamation marks.

**Depth.** Real documentation for engineers: concrete code (TypeScript, CLI, JSON, SQL where it helps), exact
option names, error codes, and action names (`compute:reservations:create`, from `generated/api.json`), states and
transitions, limits and defaults, failure behavior. Prefer 400 to 1,500 words per page; index pages orient and link.

**Accuracy over coverage.** The sources of truth are `packages/*/src`, the package READMEs (some status lines are
stale; trust the code), PLAN.md, `generated/*.json`, the examples, the tests, and `CHANGELOG.md`. Every identifier
must exist in the source. When something is only designed in PLAN.md, say it is planned and for which phase; a
method whose status is `planned` is planned for the phase shown. Nothing is on npm yet, and the Go daemon `bcd` is
written in `daemon/` but not built or released; the TypeScript FakeDaemon in `@better-compute/testing` speaks the
real protocol for tests, the simulator, and `better-compute dev --sim N`.

**MDX safety.** Outside code, `{`, `}`, `<`, and `>` start JSX or expressions. Put identifiers and anything with
braces or angle brackets in backticks, write "less than" in words, or escape as `\{`. Comments are
`{/* like this */}`, never `<!-- -->`. Every JSX tag is closed or self-closing. No bare `<` in tables.

**Code blocks** always carry a language (`ts`, `tsx`, `js`, `json`, `jsonc`, `bash`, `sh`, `sql`, `yaml`, `http`,
`diff`, `ini`, `toml`, `proto`, `go`, `dockerfile`, `powershell`, `text`) and, when it helps, a title:
` ```ts title="compute.ts" `. Shiki notation works in comments: `// [!code highlight]`, `// [!code ++]`,
`// [!code --]`. Do not use `twoslash` or auto type tables: the pipeline keeps Twoslash wired, but no content
depends on it.

**Links** between pages are absolute (`/docs/guides/capacity/placement`) and name existing pages only. Do not put
`#anchors` on links to guide pages. API methods link to the generated reference:
`/docs/reference/api/{group-in-kebab-case}#{method-in-lowercase}`, for example `/docs/reference/api/reservations#create`
or `/docs/reference/api/join-tokens#create`. The CLI is `/docs/reference/cli`, errors `/docs/reference/errors`.

**Diagrams** are ` ```mermaid ` fences (`flowchart`, `sequenceDiagram`, `stateDiagram-v2`) where a flow or state
machine is clearer drawn. Keep labels short and quote labels that contain punctuation.

**Components** available on every page without importing:

| Component                                                                   | Use                                                                                                                       |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `<Callout type="info\|warn\|error\|success\|idea" title="...">`             | Asides. Keep them rare and short.                                                                                         |
| `<Cards>` / `<Card title href icon?>`                                       | Link grids ("Next steps").                                                                                                |
| `<Tabs items={['PostgreSQL', 'PGlite']}>` / `<Tab value="PostgreSQL">`      | Alternatives.                                                                                                             |
| `<Steps>` / `<Step>`                                                        | Ordered procedures (`### Title` headings inside each step).                                                               |
| `<Accordions type="single">` / `<Accordion title>`                          | FAQs and optional detail.                                                                                                 |
| `<Files>` / `<Folder name defaultOpen>` / `<File name>`                     | Project layouts.                                                                                                          |
| `<TypeTable type={{ name: { type, description, default?, required? } }} />` | Option and field tables.                                                                                                  |
| `<FeatureGrid>` / `<Feature icon title href?>`                              | Overview tiles.                                                                                                           |
| `<PackageTable filter={['@better-compute/capacity']} />`                    | Package cards from `generated/packages.json`; without a filter, every publishable package.                                |
| `<PackageGraph />`                                                          | The internal dependency graph of the workspace packages, read from their manifests (umbrella left out).                   |
| `<Term id="reservation">reservations</Term>`                                | A glossary term with its definition in a hover card (ids in `data/glossary.json`). Use it on the first mention of jargon. |
| `<Glossary />`                                                              | Every glossary term alphabetically; each term's anchor is its slug (`#allocation-lease`).                                 |
| `<ApiEndpoint group="reservations" method="create" />`                      | A method's route, server and client calls, IAM action (or Public), and "Planned" badge, from the catalog.                 |
| `<ApiGroupSummary group="reservations" />`                                  | A group's method count, served count, and how to call it.                                                                 |
| ` ```mermaid ` fences                                                       | Diagrams.                                                                                                                 |
| ` ```npm ` fences                                                           | `npm i x` rendered as npm / pnpm / yarn / bun tabs. Say near install commands that nothing is on npm yet.                 |

Icons come from the site's registry, `lib/icons.ts`, which maps semantic names to react-icons (Remix Icon, the set
BoardUI is drawn with; Simple Icons for vendor logos). Import them at the top of the page for `Feature` and `Card`
props: `import { Cpu } from '@/lib/icons';`. Frontmatter and `meta.json` `icon` fields use the same names; an
unknown name logs `[icons] Unknown icon` during the build.
